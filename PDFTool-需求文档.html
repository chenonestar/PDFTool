1. 项目概述

PDFTool 是一款自己用的 Windows 桌面 PDF 编辑工具，不需要安装，也不联网。目标是在日常使用中替代福昕、WPS 等商业 PDF 编辑器，覆盖下面几类需求：

  • 阅读和整理 PDF：合并、拆分、重排页面等；
  • 直接修改 PDF 里原有的文字和图片，尽量接近原生编辑的体验（这是本项目的重点）；
  • 批注、签名、填写和制作表单；
  • 扫描件 OCR 识别；
  • PDF 和图片、文本、Word、Office 文档之间的转换。

界面采用"编辑器 + 工具箱"结合的形式：主界面是类似 Acrobat、福昕的文档编辑器，另有一个工具箱面板，用来批量处理合并、压缩、加水印、OCR、格式转换等任务。

2. 运行环境与发布形态

项目要求
操作系统Windows 10 / 11，64 位
运行依赖系统自带的 Microsoft Edge WebView2 Runtime（Win10 一般已随 Edge 安装，Win11 内置）
安装方式绿色免安装：解压即用，不写注册表，不往 AppData 写数据，整个文件夹拷走即可使用
网络完全离线运行，不联网
体积目标主程序约 20–30MB（含 MuPDF WASM），OCR 模型另计约 15–20MB

2.1 发布目录结构

PDFTool/
├── PDFTool.exe              # 主程序（Wails 打包，前端资源内嵌）
├── ocr/                     # OCR 模型与运行库
│   ├── onnxruntime.dll
│   ├── det.onnx             # 文字检测模型
│   ├── rec.onnx             # 文字识别模型
│   └── keys.txt             # 字典
└── data/                    # 程序首次运行时自动创建
    ├── settings.json        # 设置
    ├── recent.json          # 最近打开的文件
    ├── signatures/          # 签名库
    ├── stamps/              # 自定义图章
    └── backup/              # 覆盖保存前的原文件备份
备选方案 如果某台电脑缺少 WebView2，可以把微软提供的 WebView2 Fixed Version 运行时放进程序目录，实现完全不依赖系统组件（体积会增加约 150MB）。默认版本不带。

3. 技术方案

3.1 技术选型

部分选型说明
程序外壳Wails v2Go 后端 + TypeScript 前端，打包为单个 exe
前端Vite + TypeScript + Svelte轻量；框架待确认，可换成 React / Vue
PDF 引擎MuPDF（mupdf.js，WASM）在前端的 Web Worker 中运行，负责渲染、结构化文字提取、内容编辑、批注、表单、页面操作、保存。放在 Worker 里，处理大文件时界面不卡
中文字体系统字体由 Go 后端从 C:\Windows\Fonts 读取宋体、黑体、微软雅黑、楷体等，不打包大字体；保存时只嵌入用到的字（字体子集化），控制文件体积
Go 后端Go 标准库 + Wails 绑定文件读写、覆盖保存与备份、系统字体枚举与读取、OCR 推理、调用 Office/WPS 转换、命令行参数（支持双击 PDF 用本程序打开）、设置存储
OCRPaddleOCR（PP-OCR）模型 + ONNX Runtime中文识别准确率明显好于 Tesseract；推理放在 Go 端还是前端，到 OCR 阶段前再做一次选型验证
Office 转 PDFCOM 自动化调用本机已安装的 Microsoft Office 或 WPS 导出 PDF；本机没装时该功能不可用

文件打开 / 保存 / 备份 · 系统字体读取 · OCR 推理（ONNX Runtime） · Office/WPS COM 转换 · 设置与数据存储 · 命令行参数

4.3 正文编辑（重点）

功能说明优先级
段落编辑点击文字进入段落编辑状态，显示可编辑文本框；尽量匹配原字体、字号、颜色、行距；修改后在原段落区域内自动换行重排P0
缺字回退原字体是子集、缺少新输入的字时，自动换用相近的系统中文字体P0
文本块增删新增文本块（选择字体、字号、颜色）；删除整个文本块P0
文字格式修改选中文字的字号、颜色、粗细P1
图片编辑选中图片后移动、缩放、替换、删除、导出P1
涂黑（Redact）框选区域或搜索关键词，真正删除区域内的文字和图片内容（不只是盖一个黑框）P1
效果预期 电子版 PDF 改几句话、改一段文字，目标效果接近福昕。以下情况效果会打折扣：表格里的文字、竖排文字、艺术字、多栏混排。文字只在原段落范围内重排，不会跨页、跨栏自动续排。实际效果在阶段 0 用真实文件验证。

功能说明优先级

5. 非功能需求

类别要求
启动速度冷启动 2 秒内显示主界面
流畅度100 页以内的文档翻页、缩放流畅；500 页以上的文档缩略图和页面按需加载
界面响应渲染、保存、OCR 等耗时操作在 Worker 或后端执行，界面不卡；长任务显示进度，可取消
数据安全不联网，文件不外传；保存采用安全写入 + 自动备份
便携所有数据存放在程序目录的 data/ 下，不写注册表、不写 AppData
兼容性能打开常见 PDF：Word / WPS 导出的、扫描件、带表单的、带加密的（需输入密码）

6. 不做的内容

  • 数字证书签名（基于 CA 证书的电子签章）
  • XFA 动态表单
  • 跨页、跨栏的文字自动续排
  • 高保真 PDF 转 Word（只做"尽力还原"版本）
  • PDF/A 合规检查与转换
  • 多人协作、云同步
  • macOS / Linux 版本

7. 开发计划

先验证风险最大的正文编辑，再搭底座，然后按使用价值依次推进。每个阶段结束都有能用的成果。

阶段 0

技术验证

搭好 Wails 项目骨架；让 mupdf.js 在 WebView2 的 Worker 里跑起来；完成页面渲染和"点段落 → 改字 → 保存"的最简原型；验证系统字体嵌入。

验收：用 5–10 个真实 PDF 测试，确认文字编辑效果可以接受。效果不达标则在此阶段调整方案。

阶段 1

阅读器底座

多标签、缩略图、书签目录、缩放、搜索、选择复制；打开、覆盖保存、自动备份、另存为；撤销 / 重做框架；设置存储。

验收：可以作为日常 PDF 阅读器使用，保存与备份可靠。

阶段 2

正文编辑完善

段落编辑、缺字回退、文本块增删、文字格式、图片编辑、涂黑。

验收：4.3 节的 P0 / P1 功能全部可用。

阶段 3

页面操作 + 工具箱面板

4.2 节全部功能；工具箱面板框架及批量处理。

阶段 4

批注与签名

4.4 节全部功能，含签名库与图章。

阶段 5

表单

4.5 节全部功能。

阶段 6

OCR

先做 OCR 推理放置位置（Go 端 / 前端）的选型验证，再实现 4.6 节功能。

阶段 7

格式转换

4.7 节全部功能。

8. 风险与对策

风险影响对策
正文编辑效果达不到预期核心功能体验差阶段 0 先用真实文件验证；不达标时降级为"擦除原文字 + 原位重写"的方式
原 PDF 字体是子集，缺字新输入的字显示不出来自动回退到相近的系统中文字体；保存时嵌入新字体子集
mupdf.js 在 WebView2 中处理大文件的性能和内存大文件卡顿在 Worker 中运行；按需渲染；阶段 0 顺带测试大文件
OCR 模型体积与识别精度程序变大或识别不准采用 PP-OCR 轻量模型；阶段 6 前做选型验证
PDF 转 Word 效果有限复杂版式还原差定为 P2，"尽力还原"，不作为核心功能
电脑缺少 WebView2程序无法启动启动时检测并提示；备选 Fixed Version 运行时
许可说明 MuPDF（mupdf.js）采用 AGPL 许可。本项目个人自用，不对外分发，不受影响；如果以后要分发给他人且不开源，需要购买 MuPDF 商业授权，或把引擎换成 PDFium（BSD 许可）。
